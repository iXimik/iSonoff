# 07. SONOFF + GoSHa AI OS: план интеграции

**Статус:** данный этап *ещё не реализован* в эксперименте. Подтверждены Tasmota, Wi-Fi и управление реле из веб-интерфейса. Этот документ — план дальнейшей интеграции, а не отчёт об успешно запущенной автоматизации.

## Архитектура

```text
 GoSHa AI OS / Python / dashboard
               |
      локальная доверенная сеть
               |
        MQTT broker (пример: Mosquitto)
               |
    MQTT с учётной записью и ACL
               |
    SONOFF Basic / Tasmota 16.0 RU
               |
           Реле ON/OFF
```

Для бытовой сети предпочтительно не выставлять Tasmota, HTTP и MQTT напрямую в интернет. Для удалённого доступа использовать отдельный защищённый VPN с правилами доступа. Брокер не нужен для ручной работы через веб-интерфейс, но удобен для автоматизации.

## Шаг 1. Подготовить брокер

Создать MQTT-брокер на домашнем сервере / локальной VM; для каждого устройства отдельную учётную запись с минимальными правами. Защитить доступ к TCP 1883 сетевыми правилами, при необходимости применять защищённое соединение. **Не оставлять anonymous-подключение в общей сети**.

## Шаг 2. Настроить Tasmota

«Настройки» → «Настройки MQTT»:

- Host — локальный IP/имя брокера.
- Port — по умолчанию 1883 (не путать с публичным доступом).
- User/Password — отдельная учётная запись устройства.
- Topic — уникальное имя, например `gosha_sonoff1`.
- MQTT включён в «Прочие настройки».

Данные реального Wi-Fi и брокера никогда не записывать в git. Проверить в консоли Tasmota сообщения о подключении MQTT.

## Шаг 3. Команды и статусы

При стандартном `FullTopic = %prefix%/%topic%/` для `gosha_sonoff1`:

| Операция | MQTT topic | Payload |
|---|---|---|
| Включить | `cmnd/gosha_sonoff1/POWER` | `ON` |
| Выключить | `cmnd/gosha_sonoff1/POWER` | `OFF` |
| Запросить состояние | `cmnd/gosha_sonoff1/POWER` | пустой |
| Подтверждение | `stat/gosha_sonoff1/POWER` | `ON` / `OFF` |
| Статус доступности | `tele/gosha_sonoff1/LWT` | `Online` / `Offline` |

Для проверки с `mosquitto_pub` (после установки клиентских утилит и настройки брокера):

```powershell
$Broker = "<BROKER_IP>"
$User = "<MQTT_USER>"
# Указать пароль безопасно в настройках клиента, не сохранять в git/истории команд.
# Примеры топиков, не выполняемые автоматически:
# mosquitto_pub -h $Broker -u $User -t "cmnd/gosha_sonoff1/POWER" -m "ON"
# mosquitto_sub -h $Broker -u $User -t "stat/gosha_sonoff1/#" -v
```

Указывать пароль в командной строке небезопасно: он может попасть в историю или список процессов. Для действительного запуска используйте безопасное управление секретами и настройки Mosquitto.

## Шаг 4. GoSHa AI OS

В Python использовать `paho-mqtt`, реализовать:

1. Подключение к брокеру с аутентификацией.
2. Публикацию **идемпотентных** команд `ON` / `OFF` (не `TOGGLE` в автоматических сценариях).
3. Подписку на `stat/+/POWER` и `tele/+/LWT`.
4. Таймаут подтверждения, понятный статус недоступности, журнал событий.
5. Правила, не допускающие несанкционированного включения важных нагрузок после восстановления питания.

Состояние GoSHa UI синхронизировать с сообщением Tasmota, а не считать успешное отправление команды доказательством переключения контактов.

## HTTP API — с оговорками

В экранной диагностике этого SONOFF указано `HTTP API: Блокирован`. Фактическую доступность `/cm?cmnd=...` нужно проверить отдельно и только в доверенной сети. **SetOption128 — это проверка HTTP Referer, а не команда «включить HTTP API».** Мы не предлагаем отключать защиту ради обхода запрета. Предпочтителен MQTT.

## Дополнительно

- Закрепить DHCP-адрес на роутере.
- Проверить сигнал Wi-Fi. В момент снятия диагностики RSSI был **−78 dBm** (слабый).
- Сохранить резервную копию настроек Tasmota локально.
- Протестировать реакцию на отключение питания, разрыв Wi-Fi и брокера **без опасной нагрузки**.
- Рассматривать автоматизацию сетевых нагрузок только после полноценной проверки электробезопасности.
